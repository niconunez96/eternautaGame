# Godot QA setup

## Goal
Add reproducible local and CI playtest automation to the Godot 4.6 project, alongside existing GUT tests.

## Scope
- Vendor a pinned compatible Godot QA addon under `addons/godot_qa`.
- Add a logic smoke scenario that launches `main.tscn`, proves player movement through semantic input, and opens the pause UI.
- Add Makefile commands for logic QA and a visual-QA entrypoint.
- Replace the placeholder CI with Godot 4.6/Godot QA execution.
- Document local use, visual baseline workflow, and Steam Deck limitation.

## TDD/verification
1. Add the JSON scenario before vendoring the runner and observe the command fail (RED).
2. Vendor the runner at its addon root and run the scenario headlessly (GREEN).
3. Run existing `make verify`, QA, Linux debug export, and `git diff --check`.

## Non-goals
- No screenshots/baselines committed until captured under CI.
- No claim of Steam Deck hardware automation or Verified status.
- Do not replace GUT: it remains the unit/integration test layer.
